## Limites da evidência

Orçamentos, agenda e dashboard analítico são necessidades propostas pelo usuário ou melhorias de produto, **não telas comprovadas**. Problema, observações, checklist, comissões, plano de contas, modelos, relatórios, notas fiscais, configurações, administração, fidelidade e histórico têm botões/abas, mas suas telas internas não foram fornecidas. Não inventar detalhes e apresentá-los como cópia funcional verificada.

## Fluxos mapeados

1. Cliente → veículos → histórico → nova OS → problema/observações → serviços + profissional → produtos/quantidades → desconto → pagamento → finalizar → imprimir → contas a receber → baixa → caixa.
2. Produtos → fornecedor → compra → estoque → consumo na OS/venda. Integração compra/financeiro é proposta arquitetural; imagem não prova a regra de geração automática.
3. Venda rápida → consumidor/cliente → produtos → desconto → pagamento → finalizar → impressão/recebimento.
4. Conta a pagar → plano/modelo → vencimento → baixa → saída de caixa.
5. Notificação → lista filtrada → registro correspondente.
6. Profissional → serviços realizados → comissões/recibos (detalhes não visíveis).

## Recorte inicial e evolução

Primeiro incremento: autenticação local, associação usuário/oficina, dashboard operacional calculado, clientes, veículos, catálogo, profissionais, orçamento convertido em OS, itens, descontos, estados da OS, impressão, baixa de peças na conclusão, recebíveis e baixa financeira. Pesquisas, filtros e persistência real.

Próximos incrementos: compras/fornecedores completos, venda rápida, contas a pagar/caixa completos, agenda, parcelamento/adiantamento/taxas, comissões e lucro, checklist, relatórios avançados, configuração administrativa de usuários, auditoria ampliada. Notas fiscais/e-mail ficam para integração futura. **Tempario, tempo técnico e automações relacionadas estão fora do escopo.**
